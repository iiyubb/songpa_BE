### 학습 내용

#### 1. Chapter 01 - MyBatis 연결 설정 (`10_mybatis/chap01_connection-config`)

##### 1-1. MyBatis란?

JDBC의 반복 코드(Connection 생성, PreparedStatement 준비, ResultSet 처리, 자원 반납)를 제거하고 SQL을 자바 코드에서 분리해 관리하는 SQL 매핑 프레임워크다.

```
JDBC         : 개발자가 Connection · Statement · ResultSet을 직접 열고 닫아야 함
MyBatis      : SqlSession 하나로 CRUD 실행, SQL은 XML 또는 어노테이션으로 분리
Spring JDBC  : JdbcTemplate으로 반복 코드 제거, SQL은 코드에 직접 작성
```

##### 1-2. Java Config 방식 — 코드로 설정

```java
// 1. Environment (트랜잭션 매니저 + DataSource)
Environment environment = new Environment(
        "dev",
        new JdbcTransactionFactory(),                       // 개발자가 commit/rollback 직접 호출
        new PooledDataSource(DRIVER, URL, USER, PASSWORD)  // 커넥션 풀 사용
);

// 2. Configuration 생성 + Mapper 등록
Configuration configuration = new Configuration(environment);
configuration.addMapper(Mapper.class);  // MyBatis가 이 인터페이스를 관리

// 3. SqlSessionFactory (앱 전체에서 딱 하나)
SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(configuration);

// 4. SqlSession 열기
SqlSession session = factory.openSession(false); // false = auto-commit 비활성화

// 5. Mapper 가져와서 쿼리 실행
Mapper mapper = session.getMapper(Mapper.class);
Date date = mapper.selectSysdate();
session.close();
```

- `JdbcTransactionFactory` → 개발자가 `commit()`/`rollback()` 직접 호출
- `ManagedTransactionFactory` → WAS나 Spring 같은 외부 환경이 트랜잭션 관리
- `PooledDataSource` → 커넥션 풀 사용 (실무 표준) / `UnpooledDataSource` → 매번 새 연결 (테스트용)

어노테이션으로 SQL을 메서드에 직접 붙이는 방식:

```java
public interface Mapper {
    @Select("SELECT CURDATE()")
    java.util.Date selectSysdate();
}
```

##### 1-3. XML Config 방식 — `mybatis-config.xml`으로 설정

```xml
<configuration>
    <environments default="dev">
        <environment id="dev">
            <transactionManager type="JDBC"/>
            <dataSource type="POOLED">
                <property name="driver" value="com.mysql.cj.jdbc.Driver"/>
                <property name="url" value="jdbc:mysql://localhost/menudb"/>
                <property name="username" value="ohgiraffers"/>
                <property name="password" value="ohgiraffers"/>
            </dataSource>
        </environment>
    </environments>
    <mappers>
        <mapper resource="mapper.xml"/>  <!-- XML Mapper 파일 위치 -->
    </mappers>
</configuration>
```

설정 파일을 읽어 SqlSessionFactory를 만드는 코드:

```java
InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(inputStream);
SqlSession session = factory.openSession(false);

// Mapper 인터페이스 없이 "namespace.id" 문자열로 쿼리 직접 실행
Date date = session.selectOne("mapper.selectSysdate");
```

#### 2. Chapter 02 - SqlSession 생명주기 (`10_mybatis/chap02-lifecycle`)

##### 2-1. SqlSessionFactory vs SqlSession 생명주기

| 객체 | 범위 | 생성 횟수 |
|------|------|-----------|
| `SqlSessionFactory` | 애플리케이션 전체 | 딱 하나 (싱글톤) |
| `SqlSession` | 요청 하나 (메서드 단위) | 매번 새로 열고 닫음 |

##### 2-2. Template 클래스 — 싱글톤으로 SqlSessionFactory 관리

```java
public class Template {

    private static SqlSessionFactory sqlSessionFactory; // static = 앱 종료까지 유지

    public static SqlSession getSqlSession() {
        if (sqlSessionFactory == null) {
            InputStream inputStream = Resources.getResourceAsStream("mybatis-config.xml");
            sqlSessionFactory = new SqlSessionFactoryBuilder().build(inputStream);
        }
        return sqlSessionFactory.openSession(false); // SqlSession은 매번 새로 생성
    }
}
```

- `SqlSessionFactory`의 hashCode는 항상 동일 → 하나의 인스턴스 재사용
- `SqlSession`의 hashCode는 호출마다 다름 → 매번 새 세션 생성 후 `close()`

#### 3. Chapter 03 - CRUD (`10_mybatis/chap03_crud`)

##### 3-1. section01 — XML Mapper + DAO 패턴

SQL과 컬럼-DTO 매핑을 XML에 작성하고, DAO에서 `sqlSession.selectList("namespace.id")` 형태로 호출한다.

`menu-mapper.xml`에서 resultMap으로 스네이크 → 카멜 매핑:

```xml
<resultMap id="menuResultMap" type="com.ohgiraffers.section01.xmlconfig.MenuDTO">
    <id property="code" column="menu_code"/>         <!-- PK 컬럼 -->
    <result property="name" column="menu_name"/>
    <result property="price" column="menu_price"/>
    <result property="categoryCode" column="category_code"/>
    <result property="orderableStatus" column="orderable_status"/>
</resultMap>

<select id="selectAllMenu" resultMap="menuResultMap">
    SELECT menu_code, menu_name, menu_price, category_code, orderable_status
    FROM tbl_menu WHERE orderable_status = "Y" ORDER BY menu_code
</select>

<insert id="insertMenu" parameterType="com.ohgiraffers.section01.xmlconfig.MenuDTO">
    INSERT INTO tbl_menu (menu_name, menu_price, category_code, orderable_status)
    VALUES (#{name}, #{price}, #{categoryCode}, 'Y')
</insert>
```

- `<id>` : PK 컬럼, `<result>` : 일반 컬럼
- `#{name}` : DTO의 getter 이름(`getName()`)과 매핑 — SQL Injection 방지 PreparedStatement 사용

DAO에서 호출:

```java
public List<MenuDTO> selectAllMenu(SqlSession sqlSession) {
    return sqlSession.selectList("MenuMapper.selectAllMenu"); // namespace.id
}

public int insertMenu(SqlSession sqlSession, MenuDTO menu) {
    return sqlSession.insert("MenuMapper.insertMenu", menu);
}
```

##### 3-2. section02 — 어노테이션 방식 Mapper

XML 대신 인터페이스 메서드에 어노테이션으로 SQL과 resultMap을 붙인다.

```java
public interface MenuMapper {

    @Results(id = "menuResultMap", value = {
            @Result(id = true, property = "code", column = "menu_code"),
            @Result(property = "name", column = "menu_name"),
            @Result(property = "price", column = "menu_price"),
            @Result(property = "categoryCode", column = "category_code"),
            @Result(property = "orderableStatus", column = "orderable_status")
    })
    @Select("SELECT menu_code, menu_name, menu_price, category_code, orderable_status "
            + "FROM tbl_menu WHERE orderable_status = 'Y' ORDER BY menu_code")
    List<MenuDTO> selectAllMenu();
}
```

서비스에서는 `getMapper()`로 프록시 객체를 받아 메서드를 직접 호출한다:

```java
MenuMapper menuMapper = sqlSession.getMapper(MenuMapper.class);
return menuMapper.selectAllMenu();
```

##### 3-3. section03 — 인터페이스 + XML 연결 (권장 방식)

인터페이스는 메서드 시그니처만 선언하고, SQL은 XML에 작성한다. XML-인터페이스 연결 규칙 4가지:

```
1. XML은 인터페이스와 동일한 패키지 경로에 위치
2. XML의 namespace = 인터페이스의 풀 클래스명
3. XML 파일명 = 인터페이스 파일명과 일치 (MenuMapper.java ↔ MenuMapper.xml)
4. XML의 id = 인터페이스의 메서드명과 일치
```

```xml
<!-- namespace가 인터페이스 풀 패키지명 -->
<mapper namespace="com.ohgiraffers.section03.remix.MenuMapper">
    <select id="selectAllMenu" resultMap="menuResultMap"> ... </select>
    <insert id="insertMenu" parameterType="com.ohgiraffers.section03.remix.MenuDTO"> ... </insert>
</mapper>
```

DML(INSERT/UPDATE/DELETE)의 트랜잭션 처리 패턴:

```java
public boolean registMenu(MenuDTO menu) {
    SqlSession sqlSession = getSqlSession();
    try {
        MenuMapper menuMapper = sqlSession.getMapper(MenuMapper.class);
        int result = menuMapper.insertMenu(menu);
        if (result > 0) {
            sqlSession.commit();    // 성공 → DB 영구 반영
        } else {
            sqlSession.rollback();  // 실패 → 원상 복구
        }
        return result > 0;
    } catch (RuntimeException e) {
        sqlSession.rollback();
        throw e;
    } finally {
        sqlSession.close();         // 항상 세션 닫기
    }
}
```

- 조회(SELECT)는 트랜잭션 불필요 → `try-finally`로 close만 처리
- DML은 `commit()`/`rollback()`을 명시적으로 호출해야 DB에 반영됨 (auto-commit=false)

#### 4. Chapter 04 - Dynamic Query (`10_mybatis/chap04_dynamic-query`)

##### 4-1. `<if>` — 조건에 따라 SQL 조각 포함/제외

```xml
<select id="selectMenuByPrice" parameterType="hashmap" resultMap="menuResultMap">
    SELECT ... FROM TBL_MENU A WHERE A.ORDERABLE_STATUS = 'Y'

    <!-- price가 0 이상 10000 이하일 때만 이 조건 추가 -->
    <if test="price gte 0 and price lte 10000">
        <![CDATA[ AND A.MENU_PRICE < #{ price } ]]>
    </if>

    <!-- price가 10000 초과 20000 이하일 때 -->
    <if test="price gt 10000 and price lte 20000">
        AND A.MENU_PRICE BETWEEN 10000 AND #{ price }
    </if>
    ORDER BY A.MENU_CODE
</select>
```

- OGNL 표현식 사용: `gt`(>), `gte`(>=), `lt`(<), `lte`(<=), `and`, `or`
- `<![CDATA[ ... ]]>` : XML에서 `<` 기호를 그대로 쓰면 파싱 오류가 나므로 CDATA 섹션으로 감쌈

##### 4-2. `<if>`로 동적 JOIN과 조건 처리

condition 값에 따라 JOIN 여부와 WHERE 조건을 다르게 적용:

```xml
<select id="searchMenu" parameterType="SearchCriteria" resultMap="menuResultMap">
    SELECT ... FROM TBL_MENU A

    <!-- condition == 'category'일 때만 JOIN 추가 -->
    <if test="condition == 'category'">
        JOIN tbl_category B ON (A.CATEGORY_CODE = B.CATEGORY_CODE)
    </if>
    WHERE A.ORDERABLE_STATUS = 'Y'

    <if test="condition == 'name'">
        AND A.MENU_NAME LIKE CONCAT('%', #{ value }, '%')
    </if>
    <if test="condition == 'category'">
        AND B.CATEGORY_NAME = #{value}
    </if>
</select>
```

`SearchCriteria` DTO로 검색 조건을 묶어서 파라미터로 전달:

```java
public class SearchCriteria {
    private String condition; // "name" or "category"
    private String value;     // 검색값
}
```

서비스에서:
```java
SearchCriteria criteria = new SearchCriteria("name", "마늘");
mapper.searchMenu(criteria);
```

### 핵심 정리

MyBatis 설정 방식 2가지
- Java Config: `Environment` → `Configuration` → `SqlSessionFactoryBuilder().build(config)` 코드로 구성
- XML Config: `mybatis-config.xml` → `Resources.getResourceAsStream()` → `SqlSessionFactoryBuilder().build(stream)` 파일로 구성

SqlSession 생명주기
- `SqlSessionFactory` : 앱 전체에서 싱글톤으로 하나만 유지 (Template 클래스로 관리)
- `SqlSession` : 요청마다 열고 닫음 (`finally` 블록에서 반드시 `close()`)

Mapper 연결 3가지 방식

| 방식 | SQL 위치 | 특징 |
|------|---------|------|
| DAO + namespace.id | XML | `sqlSession.selectList("namespace.id")` 문자열 방식 |
| @Select 어노테이션 | 인터페이스 | SQL이 코드에 붙어있어 간단하지만 복잡한 쿼리는 불편 |
| 인터페이스 + XML 연결 | XML | namespace = 풀 클래스명, id = 메서드명 규칙 준수 필요. 복잡한 쿼리에 권장 |

resultMap — 스네이크 → 카멜 매핑
- DB 컬럼명(스네이크_케이스)과 DTO 필드명(camelCase)이 다를 때 `<resultMap>`으로 명시적 매핑
- `<id>` = PK 컬럼, `<result>` = 일반 컬럼

DML 트랜잭션 패턴
- `openSession(false)` → auto-commit 비활성화
- result > 0이면 `commit()`, 아니면 `rollback()`
- 예외 발생 시 catch에서 `rollback()` 후 재throw, finally에서 `close()`

동적 쿼리 핵심 태그
- `<if test="조건">` : OGNL 표현식으로 조건 판별, 조건에 맞을 때만 SQL 조각 추가
- `<![CDATA[ ]]>` : XML 특수문자(`<`, `>`)를 SQL에 그대로 쓸 때 감싸는 섹션
- (학습 예정) `<where>`, `<set>`, `<trim>`, `<foreach>` 태그들로 더 복잡한 동적 쿼리 처리

### 느낀 점 / 회고

오늘은 MyBatis를 처음 배우면서 "SQL 매핑 프레임워크"가 어떤 문제를 해결하려는 건지 확실히 느꼈다. JDBC로 직접 연결하면 Connection 열기 → Statement 준비 → 쿼리 실행 → ResultSet 순회 → 자원 반납까지 한 번의 조회에도 20줄이 넘는 반복 코드가 생기는데, MyBatis는 그 구조를 SqlSession 하나와 Mapper 인터페이스로 깔끔하게 추상화했다.

세 가지 Mapper 방식(DAO 직접 호출, 어노테이션, 인터페이스+XML 연결)을 모두 실습하면서 인터페이스+XML 연결 방식이 왜 권장되는지 자연스럽게 이해됐다. 어노테이션 방식은 SQL이 코드에 박혀있어서 간단한 쿼리에는 편하지만, JOIN이 여러 개 걸린 복잡한 쿼리는 자바 문자열로 쓰면 가독성이 너무 떨어진다. XML에 SQL을 분리해두면 SQL과 자바 로직의 관심사가 완전히 나뉘고, 나중에 쿼리 튜닝도 XML만 건드리면 된다는 게 실용적이었다.

트랜잭션 처리에서 `openSession(false)`로 auto-commit을 끄고 직접 `commit()`/`rollback()`을 호출해야 한다는 것, 그리고 예외 발생 시 catch에서 rollback하고 다시 throw해야 데이터 일관성이 깨지지 않는다는 패턴이 명확하게 정리됐다. 특히 finally에서 반드시 `close()`를 호출해야 커넥션 풀에 연결이 반납된다는 흐름을 이해하고 나니, SqlSession이 "요청 하나의 생명주기"와 정확히 맞아떨어지는 설계임을 느꼈다.

동적 쿼리의 `<if>` 태그는 "파라미터 값에 따라 쿼리가 달라지는 상황"을 XML 안에서 자연스럽게 표현할 수 있다는 게 인상적이었다. `<![CDATA[ ]]>` 섹션이 필요한 이유(XML 파서가 `<` 기호를 태그 시작으로 인식해버리기 때문)도 이번에 처음 명확히 이해했다. `<where>`, `<set>`, `<foreach>` 같은 나머지 태그들이 남아있는데, 이 태그들이 어떤 상황에서 `<if>`보다 더 깔끔한 해법이 되는지 이어서 살펴보고 싶다.
